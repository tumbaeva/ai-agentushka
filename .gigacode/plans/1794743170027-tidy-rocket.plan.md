# План: демо-RAG → локальный коммерческий продукт (ниша: образование/конкурсы)

## Цель
Превратить учебный Flask-RAG-дашборд в **локальный (single-instance) продукт** с **качественным русскоязычным поиском** и **отполированным UX**. Без SaaS, мульти-тенантности и биллинга. Клиент — организаторы конкурсов и вузы (Windows-машина).

Фокус по согласованию с пользователем:
- **Все 4 UX-функции**: загрузка своих документов, чат с историей, цитаты источников, аналитика качества.
- **Все 4 улучшения поиска**: сильнее embeddings, умный чанкинг, работа с запросом, тюнинг слияния и rerank.

---

## 1. Контекст: что есть и что сломано

Монолит `app.py` (~40KB) содержит всё: конфиг, загрузку документов, чанкинг, embeddings, вектор/BM25/hybrid/multi-query/rerank, генерацию, 14 Flask-роутов, eval с метриками (hit@k, recall@k, precision@k, doc_acc@k, doc_precision@k, mrr@k), сохранение снэпшотов в `search_models/<ts>/`, управление секретами. UI — один `template.html` (vanilla HTML/CSS/JS, тёмная тема).

**Критические дефекты, которые надо починить по ходу:**

1. **Reranker никогда не работает.** `from cross_encoder import CrossEncoder` — такого пакета нет; правильный импорт `from sentence_transformers import CrossEncoder`. Сейчас `HAS_CROSS_ENCODER` всегда `False` → режим `multi_query_rerank` тихо деградирует до `multi_query`.
2. **Нет загрузки сохранённых индексов.** `save_search_model` пишет снэпшот, но `init_rag()` при каждом старте заново читает документы и пересчитывает эмбеддинги (долгий старт). Загрузчика нет.
3. **Дефолтная модель — gated.** `EMB_MODEL_TYPE='frida'` → `ai-forever/FRIDA` требует `HF_TOKEN`; без него молчаливый откат на слабую для русского MiniLM.
4. **Баг разбиения `knowledge_base.md`.** `load_documents_from_knowledge_base` режет по `^## ` и берёт строку 0 как `file_name`. В реальном файле `# ` = имя документа, `## ` = внутренние разделы. Итог: `file_name` становится заголовком раздела, а eval-эталон (по именам `.docx`) никогда не совпадает → `doc_acc@k`/`doc_precision@k` в режиме `kb_md` всегда 0. Плюс `normalize_whitespace` схлопывает переводы строк, убивая структуру до чанкинга.
5. **`saveSecrets()` в `template.html` — заглушка**: собирает объект, но `fetch('/api/secrets')` не вызывает.
6. **`GET /api/secrets` отдаёт секреты в открытом виде**, при этом сервер слушает `0.0.0.0` без аутентификации → утечка в LAN.
7. **Нет upload/delete/PDF.** `load_documents_from_folder` берёт только `.docx`/`.txt`; нет эндпоинтов ingest/delete.
8. **`/api/models/config` только мутирует глобалы** — состояние (embedder/index) рассинхронизировано до `/api/rebuild`.
9. **Потоконебезопасность**: всё состояние в модульных глобалах, мутируется при threaded-запросах.
10. **Хардкод ID модели в промптах** (`ai-sage/GigaChat3-10B-A1.8B`) в обход `LLM_MODEL`.
11. **`run.bat` хардкодит `cd /d D:\!platform\...`** — непортируемо; нет venv.
12. **`requirements.txt` не запинован**; `cross_encoder` закомментирован (вводит в заблуждение); нет парсера PDF и тестов.

Замечание: `.env` (801 байт) и `search_models/2026-11-14_20-01-58/` реально присутствуют в рабочем дереве (игнорируются git).

## 2. Целевая архитектура (после рефакторинга)

Разбить монолит на импортируемый пакет + app factory, сохраняя поведение на каждом шаге.

```
app.py                      # тонкий shim: create_app()
run.py                      # dev-запуск
pyproject.toml              # метаданные + источник истины по зависимостям
requirements.txt            # запинованный (pip-compile/freeze)
requirements-dev.txt
rag_app/
  __init__.py               # create_app(): config, БД, blueprint'ы, фоновый bootstrap
  config.py                 # Settings, пути, загрузка env/секретов, реестр моделей
  logging_conf.py
  errors.py                 # типы ошибок + JSON-хендлеры
  core/
    normalize.py            # whitespace, токенизация, ё/е, стоп-слова
    loaders.py              # docx/md/pdf/txt → Document(text, section, meta)
    chunking.py             # heading-aware чанкер + ограничение по размеру + метаданные
    embeddings.py           # реестр моделей, HF cache dir, загрузка/переключение, dims
    vector_store.py         # FAISS build/search, save/load (index.faiss)
    bm25_store.py           # BM25 build/save/load (bm25.json)
    index_manager.py        # build snapshot, fingerprint, save/load, атомарная замена, lock
    query_transform.py      # rewrite/expand, синонимы, опечатки, HyDE
    retrieval.py            # vector/bm25/hybrid/multi_query/multi_query_rerank
    rerank.py               # CrossEncoder-обёртка
    generation.py           # build_rag_prompt, answer, цитаты
    eval.py                 # метрики + heatmap (сохранить формулы из CLI-скрипта)
  services/
    ingestion.py            # загрузка/удаление/переиндексация документов
    chat_store.py           # SQLite: сессии и сообщения
    settings_store.py       # persist настроек (не глобалы)
  web/
    api_blueprint.py        # /api/*
    pages_blueprint.py      # /, /docs/<f>, /heatmap
    static/  (css/js)
    templates/ (index.html)
  data/                     # workspace клиента: docs/, uploads/, chat.db, index/
```

`app.py` остаётся как shim (`from rag_app import create_app; app = create_app()`) — чтобы не ломать `run.bat` и привычный запуск.

## 3. Пошаговый план по фазам

### Фаза 0 — Безопасность и базовая гигиена (сначала!)
- Убедиться, что `.env` в `.gitignore` (уже да), убрать секреты из выдачи `GET /api/secrets` (маскировать), ограничить биндинг по умолчанию `127.0.0.1` (host из конфига).
- Починить `saveSecrets()` в JS (добавить `fetch`).
- Удалить дубли логов в корне (после остановки сервера), оставить `logs/`.
- Файлы: `app.py` (роут `/api/secrets`, `app.run`), `template.html` (JS), `.env`/config.

### Фаза 1 — Рефакторинг в пакет (без изменения поведения)
- Разнести `app.py` по модулям из раздела 2; `create_app()` + синий принты.
- Вынести конфиг в `Settings` (dataclass), убрать глобалы; ввести блокировку вокруг перестроения индекса.
- Сохранить формулы метрик и RRF 1:1 (эталон — CLI-скрипт).
- Файлы: новые модули `rag_app/**`, новый тонкий `app.py`, `run.py`.

### Фаза 2 — Качество поиска
1. **Embeddings.** Реестр моделей: `BAAI/bge-m3` (лучший русский, 1024 dim, ~2.3GB), `ai-forever/FRIDA` (требует HF_TOKEN), `intfloat/multilingual-e5-base/large`, fallback MiniLM. Локальный кэш HF (`HF_HOME`/`SENTENCE_TRANSFORMERS_HOME`), предзагрузка при первом старте, понятная ошибка при отсутствии модели и офлайне (флаг `HF_HUB_OFFLINE`). При смене модели — пометка индекса как несовместимого.
2. **Умный чанкинг.** Heading-aware: разбивать по `#`/`##` с сохранением секции; внутри раздела — абзацами, с ограничением размера и overlap. Метаданные чанка: `doc_name`, `section`, `doc_type`, `chunk_index`. Починить сплит `knowledge_base.md` (h1 = документ).
3. **Работа с запросом** (`query_transform.py`): нормализация (ё/е, регистр, опечатки через pymorphy3/симспелл), синонимы (словарь ниши: конкурс/положение/номинация), переформулировка через LLM (уже есть multi-query), HyDE (гипотетический ответ → вектор).
4. **Слияние и rerank.** Вынести веса RRF и BM25/vector в конфиг; переключаемый reranker `sentence_transformers.CrossEncoder` (`BAAI/bge-reranker-v2-m3` или `mmarco-mMiniLMv2`), корректный импорт; фильтры по метаданным (тип документа, раздел).
- Файлы: `core/embeddings.py`, `core/chunking.py`, `core/query_transform.py`, `core/retrieval.py`, `core/rerank.py`, `config.py`.

### Фаза 3 — Загрузка документов через UI
- `POST /api/documents` (multipart, .docx/.pdf/.md/.txt), `DELETE /api/documents/<id>`, авто-переиндексация (фоном, со статусом).
- Парсеры: `python-docx` (docx), `pypdf`/`pdfplumber` (pdf), markdown, txt. Хранилище: `data/uploads/` + реестр документов.
- UI: панель «Документы» с drag&drop, списком, статусом индексации, удалением.
- Файлы: `services/ingestion.py`, `core/loaders.py`, `web/api_blueprint.py`, `template.html`/новые static.

### Фаза 4 — Чат с историей + цитаты
- SQLite (`services/chat_store.py`): таблицы `sessions`, `messages` (role, text, citations JSON, ts). Чаты переживают перезапуск.
- `POST /api/chat` (session_id, сообщение) → retrieval + LLM + сохранение; история в промпт.
- **Цитаты**: из найденных чанков формировать блок с `doc_name`, `section`, точным фрагментом и подсветкой (offset'ы), ссылкой на документ; сохранять в сообщение.
- UI: чат-вкладка, история сессий, панель источников справа с подсветкой.
- Файлы: `services/chat_store.py`, `core/generation.py`, `web/api_blueprint.py`, `template.html`.

### Фаза 5 — Аналитика качества
- Перенести eval в `core/eval.py`; расширить ground-truth (сейчас 4 вопроса) при желании клиента; метрики + heatmap.
- `POST /api/eval/run` — прогон по запросу и автоматически при смене настроек (debounce); хранение истории метрик.
- UI: панель с графиками (линии по режимам/настройкам), таблица, кнопка «Запустить оценку».
- Файлы: `core/eval.py`, `web/api_blueprint.py`, `template.html`.

### Фаза 6 — Поставка как локального продукта
- `pyproject.toml` + `requirements.txt` (запинованные), `requirements-dev.txt`.
- `run.bat` → портируемый лаунчер: создаёт/активирует `.venv`, ставит зависимости, стартует `run.py`, открывает браузер. Абсолютные пути → относительные к скрипту.
- Первый запуск: `data/` workspace, визард с выбором embedding-модели и вводом ключей GigaChat, проверка соединения.
- Опционально: Dockerfile (offline-образ с предзагруженными моделями) для клиентов с Docker.
- README (установка, запуск, конфиг), `CHANGELOG`.
- Файлы: `pyproject.toml`, `requirements*.txt`, `run.bat`, README, `config.py`, `__init__.py`.

### Фаза 7 — Тесты и надёжность
- `pytest`: чанкинг (структура/метаданные), метрики eval, слияние RRF, лоадеры, ingestion, chat_store, API-эндпоинты (Flask test client).
- Обработка ошибок: единые JSON-ошибки, таймауты LLM, ретраи, понятные сообщения при отсутствии модели/ключей/офлайне.
- Файлы: `tests/**`, `errors.py`, `logging_conf.py`.

## 4. Технологические решения

| Область | Выбор | Обоснование |
|---|---|---|
| Embeddings | `BAAI/bge-m3` (default), альт. `intfloat/multilingual-e5-large`, `ai-forever/FRIDA` (HF_TOKEN) | bge-m3 — SOTA для русского/мультиязычного, локально, кэшируется |
| Reranker | `sentence_transformers.CrossEncoder` (`BAAI/bge-reranker-v2-m3` / `mmarco`) | корректный импорт, чинит мёртвый режим rerank |
| Чанкинг | heading-aware + абзацный, bounded size | сохраняет структуру документа (разделы, номинации, сроки) |
| Рерайт/ХyDE | LLM GigaChat (уже подключён) + pymorphy3 для нормализации | использует существующий стек |
| PDF | `pypdf` (или `pdfplumber` при нужде в layout) | лёгкий, чистый Python |
| Хранилище чата | SQLite (stdlib) | без внешних сервисов, переживает перезапуск, локально |
| Front-end | остаться на vanilla HTML/CSS/JS, вынести в static/ | минимум зависимостей для локальной поставки; можно добавить Chart.js (CDN/local) для графиков |
| Индексы | FAISS + BM25 + meta.json (как есть), + загрузчик | убрать пересчёт на старте |
| Тесты | pytest | стандарт |

## 5. Риски и компромиссы

- **Размер/офлайн моделей.** bge-m3 ~2.3GB — первый запуск требует интернета; для офлайн-клиентов — предзагрузка в образ/кэш + флаг `HF_HUB_OFFLINE`.
- **GPU.** На CPU bge-m3 медленнее; предусмотреть выбор модели в визарде (баланс качество/скорость).
- **Смена модели инвалидирует индекс.** Хранить `embedding_model` в meta и блокировать поиск до переиндексации с понятным сообщением.
- **Windows.** Пути, venv, кодировка; лаунчер на PowerShell/bat с относительными путями; UTF-8 везде.
- **Потокобезопасность** при фоновой переиндексации — блокировки и атомарная подмена индекса.
- **GigaChat/Cloud.ru** — внешний API: таймауты, ретраи, деградация до поиска без генерации.
- **Ниша узкая** — ground-truth для eval собирать вместе с клиентом (конкурсные вопросы).

## 6. Верификация (end-to-end, Windows)

1. **Старт:** `run.bat` → venv, установка, `data/`, визард, сервер на 127.0.0.1, браузер открылся.
2. **Поиск:** запросы по конкурсу — проверить все 5 режимов, что `multi_query_rerank` реально реранжит (лог), что цитаты указывают на верные разделы.
3. **Загрузка:** добавить .docx/.pdf/.md через UI → авто-индексация → поиск находит новый документ → удаление убирает его из выдачи.
4. **Чат:** задать несколько вопросов в сессии, перезапустить сервер → история на месте; цитаты с подсветкой кликаются.
5. **Аналитика:** запустить eval, увидеть метрики/heatmap; сменить embedding-модель → предложена переиндексация → метрики пересчитаны.
6. **Безопасность:** `GET /api/secrets` не отдаёт секреты; сервер по умолчанию не слушает LAN.
7. **Тесты:** `pytest` — зелёный.
8. **Регресс:** `python DZ_PRO_5__Retriever_hybrid_search_rerank.py` — эталон метрик совпадает с новым `core/eval.py`.

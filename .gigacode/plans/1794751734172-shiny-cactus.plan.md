# План: страница «Создать базу знаний» (сборка knowledge_base.md из документов)

## Цель
Добавить в существующий RAG Dashboard **отдельный инструмент (новую страницу)** для сборки
базы знаний из загруженных документов. Существующие страницы не переписываем: единственное
изменение в текущем UI — новая кнопка/ссылка **«Создать базу знаний» перед вкладкой «Документы»**.

Согласовано с пользователем:
- Форматы: только `.docx`, `.pdf`, `.txt`, `.md`.
- Отдельная папка для загрузок: `source_docs/` в корне проекта.
- Сборка: слияние выбранных документов в **один** `knowledge_base.md` (каждый документ → `# <имя>`).
- Управление: список файлов + удаление, порядок документов, предпросмотр результата, выбор галочками.
- Запись: сначала в **отдельный файл**, затем отдельным действием **перенос** в `docs/knowledge_base.md`.
- LLM-обработка — **опционально** (флажок), при отсутствии клиента — тихий откат к простому извлечению.

## Как устроено сейчас (ключевое)
- Фабрика: `rag_app/__init__.py` → `create_app()` создаёт `AppContext`, регистрирует `api_bp` и `pages_bp`.
  `AppContext` держит `settings`, `index`, `retriever`, `ingestion`, `llm_client()`.
- Страницы: `rag_app/web/pages.py` (Blueprint `pages_bp`), API: `rag_app/web/api.py` (Blueprint `api_bp`, `url_prefix=/api`).
- Навигация — `<nav class="tabs">` в `rag_app/templates/index.html`; кнопки с `data-tab` переключают панели,
  ссылки-вкладки (`/recommendations`, `/help`) уводят на отдельные страницы (обр. `app.js` → `document.querySelectorAll(".tabs .tab")`).
- База знаний: `Settings.kb_path` (`docs/`) + файл `knowledge_base.md`; документы разделяются H1.
  `rag_app/loaders.py` уже содержит парсеры: `_docx_paragraphs` (заголовки Word → markdown), `_pdf_text`, `_read_text_any_encoding`, `infer_category`.
- `Settings.ensure_dirs()` создаёт каталоги; `data/` в `.gitignore`.
- LLM: OpenAI-совместимый клиент (`AppContext.llm_client()`), модель `settings.llm_model` (см. `rag_app/generation.py`).
- Тесты: pytest, фикстура `client` в `tests/conftest.py` (tmp `docs/`+`data/`, `source="files"`, `enable_rerank=False`).

## Новые файлы

### 1. `rag_app/kb_builder.py` — сервис `KnowledgeBaseBuilder`
Не зависит от Flask; получает `Settings` и (опц.) LLM-клиент.
- Пути: `source_dir = settings.source_docs_path`; `build_dir = settings.data_path / "kb_build"`;
  `draft_path = build_dir / "knowledge_base.md"`; `state_path = build_dir / "state.json"`.
- Состояние (`state.json`): `{"files": {name: {"order": int, "selected": bool}}}`; новые файлы — в конец, `selected=True`.
- Методы:
  - `list_files() -> list[dict]` — `name, ext, size, chars, order, selected` (сортировка по order, затем name).
  - `save_upload(file_storage) -> dict` — проверка расширения в `{.docx,.pdf,.txt,.md}`, санитизация имени,
    защита от перезаписи, запись в `source_dir`, апдейт состояния.
  - `delete_file(name) -> bool` — удалить файл с диска + из состояния.
  - `set_order(order: list[str])` / `set_selection(selected: list[str])` — персист в `state.json`.
  - `extract(path) -> str` — извлечь текст: docx через `_docx_paragraphs` (со сдвигом уровней заголовков +1,
    чтобы имя документа осталось единственным H1), pdf через `_pdf_text`, md/txt через `_read_text_any_encoding`;
    нормализация `\u00a0`, обрезка, понижение «верхних» H1 до H2.
  - `assemble(use_llm=False, llm_client=None, llm_model="") -> (text, files_meta)` — по выбранным файлам
    (в заданном порядке) собрать `# <stem>\n\n<body>` блоки, склеенные пустой строкой.
    При `use_llm=True` каждый `<body>` прогоняется через `llm_structure(...)` с откатом к исходному тексту при ошибке/None.
  - `build(use_llm=False, ...)` — `assemble()` + запись `draft_path`; возвращает `{text, files, chars, path, llm_used}`.
  - `promote() -> dict` — копирование `draft_path` → `settings.kb_path / "knowledge_base.md"`; вернуть `{path, chars}`.
  - `draft_bytes() -> (filename, bytes)` — для скачивания.
  - `llm_structure(client, model, text, name) -> str` — промпт «приведи к аккуратному markdown, сохрани заголовки/списки/таблицы,
    ничего не добавляй»; при исключении/пустом ответе — вернуть исходный текст.

### 2. `rag_app/web/kb_builder.py` — Blueprint `kb_bp`
- Страница: `GET /kb-builder` → `render_template("kb_builder.html", title=ctx.title or "Создать базу знаний")`.
- JSON API (`url_prefix="/api/kb"`), доступ к сервису через `ctx.builder`:
  - `GET  /api/kb/files` → `{files:[...]}`
  - `POST /api/kb/upload` → multipart (ключ `file`, поддерживает несколько) → загрузка в `source_docs/`
  - `DELETE /api/kb/files/<path:name>` → удаление
  - `POST /api/kb/order` `{order:[...]}`
  - `POST /api/kb/selection` `{selected:[...]}`
  - `POST /api/kb/preview` `{use_llm:bool}` → `build()` (пишет draft), возвращает `{text, chars, files, llm_used}`
  - `POST /api/kb/promote` → `promote()` + `ctx.rebuild()` (как в `/api/documents`; ошибка переиндексации → 200 + `warning`);
    возвращает `{status, rebuilt}`
  - `GET  /api/kb/download` → `send_file` draft
  Ошибки — по образцу `api.py` (400/404/500, `{"error": ...}`).

### 3. `rag_app/templates/kb_builder.html` — новая страница
Самодостаточный шаблон (заголовок, ссылка «← На главную» на `/`), переиспользует `style.css`, `tooltip.js`.
Панели: dropzone для `.docx/.pdf/.txt/.md`; список файлов (чекбокс, имя, размер, ↑/↓ порядок, «удалить»);
опции (чекбокс «обработать через LLM», кнопка «Собрать и предпросмотреть»); предпросмотр `<pre>` + кнопка
«Перенести в базу знаний (docs/knowledge_base.md)»; статус.

### 4. `rag_app/static/kb_builder.js`
Локальные хелперы `api/$/el/esc` (по образцу `app.js`); `loadFiles()`, рендер списка, обработчики
выбора/порядка/удаления/загрузки, `preview()` → `/api/kb/preview`, `promote()` → `/api/kb/promote`.

### 5. `tests/test_kb_builder.py`
Фикстура `client` из `conftest.py`. Тесты: отказ на `.exe`; приём `.txt/.md` (файл лег в `source_docs/`);
preview содержит `# <имя>`; порядок влияет на сборку; непроставленная галочка исключается; `promote` пишет
`docs/knowledge_base.md`; preview без LLM-клиента → `llm_used=False` (тихий откат).

## Верификация
1. `python -m pytest` — все зелёные (старые + `test_kb_builder.py`).
2. `run.bat` (или `.venv\Scripts\python.exe run.py`) → `http://127.0.0.1:5555`.
3. На главной перед «Документы» видна ссылка «Создать базу знаний» → открывается `/kb-builder`.
4. Загрузить пару `.docx/.pdf/.txt` → появляются в списке (файлы реально в `source_docs/`).
5. Поменять порядок, снять галочку у одного файла → «Собрать и предпросмотреть» → в предпросмотре виден `knowledge_base.md`
   без исключённого документа и в нужном порядке; при включённом LLM и заданном ключе — текст структурирован.
6. «Перенести в базу знаний» → `docs/knowledge_base.md` перезаписан, индекс перестроен (статус в шапке),
   на вкладке «Документы» видны новые документы; «Поиск» находит фрагменты.
7. Удалить файл из списка → пропадает из `source_docs/` и из состояния.

## Открытые вопросы (не блокирующие)
- Лист draft: предлагается `data/kb_build/knowledge_base.md` (каталог уже в `.gitignore`). Альтернатива — рядом с `source_docs/`.
- Порядок: базово реализуем стрелками ↑/↓; drag&drop — как улучшение (опционально).
- `promote` перестраивает индекс автоматически (как `POST /api/documents`); при ошибке embeddings возвращаем `warning`, не 500.

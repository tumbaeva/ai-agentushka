# Справка RAG Dashboard

Подробное руководство по локальному RAG-помощнику: что это, как устроено, как пользоваться каждой вкладкой и настройкой, как подобрать лучшие параметры и что делать при ошибках.

---

## 1. Что это

Локальное веб-приложение (Flask) для умного поиска и генерации ответов по **базе знаний** — набору документов (например, о конкурсе). Работает **на одной машине**, без облака и мульти-тенантности. Клиент — организаторы конкурсов и вузы.

Что умеет:
- 5 режимов поиска (векторный, BM25, гибрид, multi-query, multi-query + rerank);
- генерацию ответов через LLM (GigaChat) со ссылками на источники;
- чат с историей;
- оценку качества поиска (метрики + тепловая карта) и **автоподбор оптимальных настроек**;
- управление базой знаний (загрузка/удаление документов).

---

## 2. Быстрый старт

```bat
run.bat
```

Скрипт создаст `.venv`, установит зависимости и запустит сервер, откроет браузер.

Вручную:
```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

Адрес по умолчанию: **http://127.0.0.1:5555**. Порт/хост можно задать в `.env`:
```
RAG_PORT=5556
RAG_HOST=127.0.0.1
```

**Первый запуск:** приложение соберёт индекс по документам из `docs/`. Пока идёт сборка, в шапке виден статус «индекс: строится…», затем «индекс готов · чанков: N».

## 3. Как устроена база знаний

- **База знаний — это один файл `docs/knowledge_base.md`.**
- Внутри него может быть **несколько документов**. Каждый документ начинается с заголовка первого уровня `# Имя документа`; подразделы — `## Раздел`, `### …`.
- Ретривер режет файл на **чанки** (фрагменты), сохраняя раздел и имя документа для ссылок.

Пример структуры:
```markdown
# Информационное письмо
## Номинации конкурса
...
## Сроки проведения
...

# Положение о конкурсе
## Общие положения
...
```

> Название конкурса приложение автоматически берёт из базы (самая частая фраза в «ёлочках» `«…»`) и показывает в шапке. Переопределить можно полем `title` в `data/settings.json`.

Доступны два **источника** поиска (настройка «Источник»):
| Источник | Что индексируется |
|---|---|
| `knowledge_base.md` (по умолчанию) | только один файл базы знаний |
| Исходные документы | все `.md/.docx/.pdf/.txt` из папки `docs/` (кроме `knowledge_base.md`) |

Конвертация `.docx/.pdf` в базу знаний выполняется **отдельным инструментом** (в это приложение не входит).

## 4. Интерфейс

Вкладки: **Документы · Аналитика · Поиск · Чат · Рекомендации · AI-агент** (зафиксированы, не прокручиваются).

### 4.1. Документы
- Показывает единый файл базы знаний и список **документов внутри** него (с числом разделов и размером).
- **Загрузка:** перетащите `.md`/`.txt` в зону или выберите файл.
  - файл с именем `knowledge_base.md` — **заменяет базу целиком**;
  - любой другой `.md`/`.txt` — **добавляется** как новый документ;
  - после загрузки индекс пересобирается автоматически.
- **Удаление:** кнопка «удалить» у документа-раздела. Если документ в базе **один**, кнопки нет (защита от случайного удаления).

### 4.2. Аналитика
Оценка качества поиска по набору тестовых вопросов.

- **Аналитика качества** — кнопки:
  - «Запустить оценку» — считает метрики по всем режимам и строит тепловую карту;
  - «Сохранить сравнение и карту» — сохраняет метрики, карту и сравнение в `data/eval/<дата>/`.
- **Тестовые вопросы** (сворачиваемый блок) — таблица: *Вопрос · Релевантные документы · Ключевые слова · удалить*.
  - «Добавить вопрос», «Придумать вопросы моделью» (LLM генерирует черновики по базе, ключевые слова подставляются автоматически), «Сохранить вопросы».
  - Хранятся в `data/eval_questions.json`.
- **Детали проверки** — выберите вопрос и режим, «Показать выдачу»: список найденных чанков с пометкой ✅/❌ (релевантен), совпавшими ключевыми словами и подсветкой фрагмента.
- **Сравнение режимов** — прогоняет произвольный вопрос по всем 5 режимам, переключение кнопками.
- **Тепловая карта** — средние метрики по режимам (0…1), сохраняется в `data/retrieval_heatmap.png` и доступна по `/heatmap`.

**Как определяется релевантность чанка (эталон):** чанк считается релевантным, если его документ входит в «Релевантные документы» **и** в тексте есть хотя бы одно «Ключевое слово». Это устойчиво к перечанкингу и смене модели.

### 4.3. Поиск
- Введите вопрос, выберите **Режим** и **k** (сколько фрагментов вернуть).
- Кнопки:
  - **«Поиск»** — только найденные фрагменты (без LLM);
  - **«Ответ»** — генерация ответа LLM + блок «Источники» с подсветкой;
  - **«Все режимы»** — сравнение выдачи всех режимов (табы по режимам).
- Нажатие кнопки показывает **только свой блок** (остальные скрываются).
- **Score** — «сырое» значение (у каждого режима своя шкала — см. §6).
- **Score (норм.)** — min-max внутри текущей выдачи: лучший → 1.000, худший → 0.000 (косметика, порядок не меняет).
- **min…max** — реальные минимальный и максимальный score этой выдачи (границы нормализации).

### 4.4. Чат
- Диалог с базой знаний; **история сохраняется** между запусками (`data/chat.db`).
- Слева — список диалогов (создать/удалить, автоназвание по первому вопросу).
- В ответе — сворачиваемый блок **«Источники (N)»**.

### 4.5. Рекомендации (`/recommendations`)
Автоподбор лучших настроек **под вашу базу**:
- Перебор **модель × размер чанка × режим** (и, опционально, температур multi-query).
- Прогоняет ваши тестовые вопросы, считает метрики, ранжирует по выбранной метрике.
- Показывает лучшую конфигурацию, лучшее по каждой модели и по каждому режиму, полную таблицу.
- Кнопки:
  - **«Применить эти настройки»** — записывает настройки и пересобирает индекс;
  - **«Сохранить лучшее и перебор»** — сохраняет в `data/recommendations/<дата>/` (`recommendations.json`, `best.json`, `sweep.csv`).

### 4.6. AI-агент (`/agent`)
Конструктор и экспорт AI-агента под ваш бренд.
- **Брендинг:** название, подзаголовок, логотип (эмодзи / инициалы / файл), favicon.
- **Цвета (7, в трёх группах):**

  | Группа | Цвет поля | Цвет шрифта |
  |---|---|---|
  | **Пользователь** | фон сообщений пользователя, кнопок-вопросов и кнопки «Отправить» | текст этих же элементов |
  | **Агент** | фон ответов агента и его эмблемы (лого); favicon | текст ответов агента |
  | **Интерфейс** | цвет фона — фон страницы и панелей; цвет поля — фон обычных кнопок и полей ввода | основной текст и заголовки |

  Плюс **библиотека палитр**: сохранить набор цветов под именем, загрузить или удалить. Кнопки «Удалить» — красные.
- **Размеры и раскладка:** размер шрифта (S/M/L), размер кнопок, скругление, ширина сайдбара, компактный режим.
- **Стиль ответа:** выбираете готовый стиль из 8 (официальный, дружелюбный, шуточный, краткий, экспертный, «объясни просто», юридический, с эмодзи), а также креативность (temperature) и длину ответа. Справа — **системный промпт**: заполняется по выбранному стилю, можно править вручную; всё сохраняется кнопкой **«Сохранить настройки»** (слева, над разделом базы знаний).
- **Источники в чате:** показывается только название документа (без имени файла базы знаний и расширений).
- **Приветствие и подсказки:** приветственное сообщение, стартовые вопросы, язык (RU/EN), показ источников, **телефон организаторов** (показывается в ответе, когда бот не может ответить — нет данных или LLM недоступен).
- **Документ базы знаний:** загрузка `.md/.txt/.docx` с авто-переиндексацией (файл `knowledge_base.md` заменяет базу целиком).
- **«Экспорт приложения»** — скачивает zip с **самостоятельным chat-only агентом** (тот же код + текущая база + лучшие подобранные настройки + ваш профиль брендинга). В приложении — только чат; распакуйте и запустите `run.bat`/`python run.py`.

> Экспортированное приложение — **только чат**: без дашборда, без панели настроек и без превью системного промпта. Брендинг/тема/стиль/приветствие/подсказки берутся из профиля.
> В архив попадает только необходимое: код агента, `docs/knowledge_base.md`, `data/settings.json` (настройки модели), `data/agent_profile.json`, **готовый индекс** `data/index/` (чанки + векторы + метаданные) и файл `.env` с ключами GigaChat. Лишнее (дашборд, отчёты оценки, история чата, черновики, чужая служебная информация) не включается — в интерфейсе агента никакой служебной информации не показывается.
> Запуск у получателя — **двойной щелчок по «Запустить агента.bat»**: он создаёт ярлык агента на рабочем столе, готовит окружение и открывает браузер; дальше можно запускать с ярлыка.

## 5. Настройки (левая панель)

**1. Модель и чанкинг**
- **Модель эмбеддинга** — чем векторизуются чанки (см. §7).
- **Chunk Size / Overlap** — размер фрагмента (символы) и перекрытие соседних.
- **Источник** — `knowledge_base.md` или исходные файлы.
- **«Пересоздать чанки»** — пересобрать чанки и индекс по текущим настройкам.
- **«Сохранить модель»** — сохранить индекс (снимок) в `data/index/`.
- **Сохранённые модели** — список снимков; «Применить» (загрузить индекс в память мгновенно) / «Удалить».

**2. Слияние и rerank**
- **RRF k** — параметр слияния Reciprocal Rank Fusion (60 по умолчанию).
- **Reranker** — cross-encoder для пересортировки кандидатов.
- **Вес вектора / Вес BM25** — вклад каждого поиска в гибридное слияние.
- **включить reranker** — вкл/выкл переранжирование.

**3. Работа с запросом**
- **переформулировка запроса** — LLM делает синонимичные варианты (для multi-query).
- **HyDE** — сначала генерируется гипотетический ответ, по нему ищется похожее.
- **Temperature (multi-query)** — температура переформулировки (только multi-query режимы).

**4. Генерация ответов**
- **LLM-модель**, **API URL**, **Temperature** (температура ответа).
- **«Сохранить настройки»** — пишет всё в `data/settings.json`.

**API Секреты** (свёрнут) — ключи GigaChat и HuggingFace → `.env`.

## 6. Режимы поиска и шкалы Score

| Режим | Как работает | Score |
|---|---|---|
| `vector` | семантический поиск по эмбеддингам (FAISS) | косинус, 0…1 |
| `bm25` | лексический поиск (BM25Okapi) | сырой BM25, может быть > 1 |
| `hybrid` | слияние vector + bm25 через RRF | сумма 1/(k+rank), ~0.01–0.03 |
| `multi_query` | несколько переформулировок запроса → RRF | ~0.01–0.05 |
| `multi_query_rerank` | то же + переранжирование cross-encoder | логит cross-encoder |

**Важно:** score **нельзя сравнивать между режимами** — у каждого своя шкала. Внутри одного режима важнее **порядок**, а не абсолютное число. Для честного сравнения используйте метрики в «Аналитике».

**RRF (гибрид):** `score = Σ w / (k + rank)`, где `w` — вес режима, `k` = RRF k.

## 7. Эмбеддинги

| Модель | Когда |
|---|---|
| **BGE-M3** (`BAAI/bge-m3`) | лучшее качество для русского, ~2.3 ГБ, скачивается один раз |
| **multilingual-e5-large** | сильная мультиязычная, ~2.2 ГБ |
| **FRIDA** (`ai-forever/FRIDA`) | gated — нужен `HF_TOKEN` |
| **MiniLM** (`paraphrase-multilingual-MiniLM-L12-v2`) | лёгкая и быстрая, слабее на русском |

- Модели кэшируются: используется стандартный кэш HuggingFace, а на «чистой» машине — локальный `data/models_cache/`.
- **Смена модели инвалидирует индекс** — после смены нажмите «Пересоздать чанки» (или примените рекомендацию).
- Без интернета первый запуск новой модели невозможен (нужно скачать веса).

## 8. Сохранение и где что лежит

| Что | Где | Как восстановить |
|---|---|---|
| Настройки UI | `data/settings.json` | читается при старте |
| Секреты | `.env` | читается при старте |
| Профиль AI-агента | `data/agent_profile.json` | читается при старте; лого/favicon — в `data/agent_assets/` |
| Снимки индекса | `data/index/<дата>/` | грузятся при старте (если отпечаток корпуса совпал) или через «Применить» |
| История чата | `data/chat.db` | SQLite, переживает перезапуск |
| Тестовые вопросы | `data/eval_questions.json` | читается в «Аналитике» |
| Артефакты оценки | `data/eval/<дата>/` | файлы (JSON/CSV/PNG) |
| Отчёты подбора | `data/recommendations/<дата>/` | файлы |
| Тепловая карта | `data/retrieval_heatmap.png`, `/heatmap` | — |

> Кнопка «Сохранить модель» **не обязательна** после смены модели — достаточно «Пересоздать чанки». Сохранение лишь кэширует индекс, чтобы при следующем запуске не пересчитывать эмбеддинги.

## 9. Ключи и подключение LLM (GigaChat)

- Ключи вводятся в «API Секреты» и пишутся в `.env`:
  - `GIGACHAT_API_KEY_SECRET` — **API-ключ из консоли Cloud.ru** (уходит как `Authorization: Bearer`);
  - `GIGACHAT_API_KEY_ID` — ID ключа (используется, если секрет пуст);
  - `HF_TOKEN` — токен HuggingFace (для gated-моделей).
- Без ключа поиск работает, но **генерация ответов недоступна** (вернётся подсказка и фрагменты).
- `GET /api/secrets` отдаёт только **маскированные** значения.

## 11. Типовые сценарии

**Выбрать лучшую модель и параметры**
1. «Аналитика» → убедитесь, что есть тестовые вопросы (можно «Придумать вопросы моделью»).
2. «Рекомендации» → отметьте модели/размеры/режимы → «Запустить подбор».
3. Посмотрите лучшую конфигурацию → «Применить эти настройки». (Опц.: «Сохранить лучшее и перебор».)

**Оценить текущее качество**
1. «Аналитика» → «Запустить оценку» → таблица метрик и тепловая карта.
2. «Детали проверки» → разобрать конкретный вопрос.

**Загрузить новую базу**
- «Документы» → перетащите `knowledge_base.md` (заменит базу) или отдельный `.md` (добавит документ).

**Поработать с вопросами**
- «Поиск» → вопрос → «Ответ» (со источниками) или «Чат» (диалог с историей).

## 12. Решение проблем

| Симптом | Причина / решение |
|---|---|
| В шапке «индекс: ошибка», поиск пуст | модель эмбеддингов не загрузилась. Проверьте лог, выберите рабочую модель (например, `local` или `bge-m3`) и «Пересоздать чанки». |
| `Ошибка LLM: invalid api key secret` | неверный ключ GigaChat. Вставьте корректный **Cloud.ru** API-ключ в «API Секреты» → «Сохранить в .env». |
| FRIDA не грузится (`Cannot copy out of meta tensor`) | проблема совместимости transformers для этой модели. Используйте `bge-m3`/`local` или обновите зависимости. |
| Первый запуск долгий | скачивается модель и строятся эмбеддинги. Дальше индекс грузится из снимка (быстро). |
| Ответ «нет в материалах», хотя факт есть | ретривер не вытащил нужный чанк; приложение добавляет в промпт «справку о документах» (первые фрагменты каждого документа). Если всё равно нет — проверьте базу. |
| Подсказки «?» обрезаются | обновите страницу (Ctrl+F5) — подсказки рисуются поверх интерфейса. |
| Изменения не видны | шаблоны/статика перечитываются при запросе; после правок Python-кода перезапустите сервер. |

## 13. Приватность и безопасность

- Всё работает **локально**; сервер по умолчанию слушает `127.0.0.1`.
- Секреты хранятся в `.env` (в `.gitignore`), наружу не выводятся (маскируются).
- Данные (индекс, чаты, настройки) — в папке `data/` (в `.gitignore`).
- Если модель генерации — внешний API (GigaChat), найденный контекст **уходит на внешний сервис**. Для полной офлайн-работы используйте локальную LLM.
